# Search-intent baseline for the Chapa guide cluster

**Date:** 2026-09-05
**Scope:** live Google and Bing autocomplete for the five seed families in `docs/plans/2026-09-05-seo-discoverability-relaunch.md` Phase 4, in English and Spanish. 55 seeds, two batches. Autocomplete is a demand proxy, not a volume figure: a phrase with no suggestions is one nobody types; a phrase that autocompletes with several tails is one people type in several ways.
**Feeds:** Phase 4 (guide titles, H1/H2 phrasing, internal anchor text). Route contracts stay as planned; only the wording targets change.

## What the data says

**1. "GitHub badges" is the head term, and it is a generator-shaped query.** Both engines complete `github badges`, `github readme badges`, `github badges generator`, `github readme badges list`, `github profile readme badges`, `how to add badges in github readme`. The singular `github profile badge` drifts toward GitHub's own achievement badges (`github user badges`, `how to get github profile badges`), which is a different intent. Chapa's guide must use the plural and the word "readme", and must answer "how do I add one" on the page, not only "what is Chapa".

**2. The dominant competitor is named in the query stream.** `github readme stats`, `github readme stats generator`, `github readme stats vercel`, `github readme stats vercel app not working`, `github readme stats not working`, `github stats card`, `github profile stats card`. These are people using or failing to use `anuraghazra/github-readme-stats`. That is Chapa's exact entry point: the guide should compare honestly ("static stats card vs. live verified badge") and mention the vercel-app reliability problem, because it is what people are searching when they are open to switching.

**3. "Developer impact" is not a search term.** `developer impact` autocompletes to impact fees, Genshin Impact and Honkai Impact. `engineering impact score`, `developer impact metrics`, `how to measure developer impact` return nothing useful in English and nothing at all in Spanish. Chapa's product language is fine for the brand, but it cannot carry a guide title. The reachable neighbours are `developer metrics` (with tails `developer productivity metrics`, `developer performance metrics`, `developer experience metrics`, `dora developer metrics`, `github developer metrics`), `engineering metrics` (`engineering metrics examples`, `engineering metrics dashboard`, `engineering metrics dora`, `engineering metrics to track`) and `measure developer productivity` (`measuring developer productivity a response to mckinsey`, `with the dx core 4`, `with github copilot`, `& ai impact`). The DORA and DX Core 4 tails mean readers already have a mental model; the guide should position Chapa's four dimensions relative to those, not pretend they do not exist.

**4. "Developer portfolio" is real, "developer portfolio badge/proof" is not.** `developer portfolio`, `developer portfolio website`, `developer portfolio github`, `developer portfolio examples`, `developer portfolio template` all autocomplete. `developer portfolio badge`, `developer portfolio proof`, `verified developer stats` do not. The portfolio guide must be titled around "developer portfolio" and "github", with the verified badge as the answer inside, not in the title.

**5. Code review metrics has narrow but multi-platform demand.** `code review metrics`, `code review metrics github`, `gitlab code review metrics`, `bitbucket code review metrics`, `ai code review metrics`, `industry benchmark for code review metrics`. Small, but it names three of Chapa's four platforms in one family, which no competitor guide does. `pull request review stats` is empty; use "code review metrics" everywhere.

**6. Multi-platform profile has no query of its own.** `multi platform developer profile` drifts to Power Platform and app frameworks. The multi-platform angle is a differentiator to state inside the badge and portfolio guides (and it already appears in the code-review tails), not a page.

**7. Spanish demand exists for badges and portfolios, not for metrics.** Real: `badges para github`, `insignias github`, `como conseguir insignias github`, `github readme` (with `stats`, `generator`, `template` tails even under `hl=es`), `perfil de github` (`profesional`, `mejorar`, `personalizar`, `compartir`), `portafolio de desarrollador web` (`ejemplos`, `junior`, `de software`), `portfolio programador` (`junior`, `backend`). Empty: `impacto desarrollador`, `métricas desarrollador`, `medir productividad desarrolladores`, `métricas de ingeniería`, `code review métricas`, `como medir el impacto de un desarrollador`. Only `métricas de desarrollo de software` returns anything, and it is academic (PSP). For the Spanish versions, the badge and portfolio guides carry the demand; the metrics and code-review guides are translations for completeness under D1 option A, where Spanish is not indexed anyway.

**8. Stray signal worth one sentence on the page.** `is github profile important` and `mejorar perfil de github` are the question behind the whole cluster. The hub can open with it.

## What changes in Phase 4

Routes are unchanged. Working titles and primary phrases are replaced:

| Route (unchanged) | Old working intent | Title target from data | H2 phrases to include |
|---|---|---|---|
| `/resources` | developer-impact hub | "GitHub profile badges, stats and developer metrics: guides" | is a GitHub profile important; how to improve a GitHub profile |
| `/resources/github-profile-badge` | "github profile badge" | "GitHub README badges: how to add a live stats badge to your profile" | github readme badges generator; github readme stats not working; github profile stats card; github markdown badges |
| `/resources/developer-impact-metrics` | "developer impact metrics" | "Developer metrics that mean something: delivery, quality, consistency, breadth" | engineering metrics examples; developer productivity metrics; DORA metrics vs individual metrics; measuring developer productivity |
| `/resources/developer-portfolio-badge` | "developer portfolio proof" | "Developer portfolio with GitHub: show verified activity, not screenshots" | developer portfolio github; developer portfolio examples; portafolio de desarrollador web ejemplos |
| `/resources/code-review-metrics` | "code review metrics" | "Code review metrics across GitHub, GitLab and Bitbucket" | code review metrics github; gitlab code review metrics; bitbucket code review metrics; industry benchmark |

Spanish titles follow the Spanish phrases above (`badges para github`, `mejorar perfil de github`, `portafolio de desarrollador web`), not literal translations of the English titles.

Two things this baseline does not give: search volume (autocomplete has no counts) and ranking difficulty. Both come from Search Console once the guides have been live for a month, which is Phase 7's job. Do not buy a keyword tool for this.
